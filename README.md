# horizon-self-consistency

A self-consistency test across forecast horizons for time-series foundation models (TSFMs).

A forecaster with a single probabilistic model of the process must satisfy the law of total probability across horizons: its direct h-step forecast must equal the chained forecast obtained by predicting one step, appending each possible next value y to the context c, predicting h-1 more steps, and averaging,

$$q_h(\cdot \mid c) \;=\; T_h(\cdot \mid c) \;=\; \int q_{h-1}(\cdot \mid c, y)\, q_1(\mathrm{d}y \mid c).$$

The measured gap $D_h$ is the mean absolute difference between the direct and chained forecasts at the nine quantile levels 0.1, ..., 0.9, divided by the width of the direct 80% interval. The chained forecast uses 32 evenly spaced one-step quantiles $y_m = Q_1((m-0.5)/32 \mid c)$. Self-consistent baselines (the exact forecaster on synthetic AR data; an AR(8) fitted per context, with Gaussian or resampled-residual noise, on real data) measure the error of the pipeline itself, and a "patchwork" forecaster (separately optimal at each horizon, using only the last value) is the positive control. The code is in `src/hsc/audit/gap.py`.

## Installation

Python 3.12 and [uv](https://docs.astral.sh/uv/):

```bash
uv sync                    # the package `hsc`, its pinned dependencies and pytest, in .venv
uv sync --extra timesfm    # also timesfm 3.0.2, needed only for TimesFM 2.5 (hsc.audit.run_timesfm)
```

All commands below are run from the repository root with the environment active (`source .venv/bin/activate`) or prefixed with `uv run`.

### Model weights

Download the checkpoints into the Hugging Face cache once, where there is network access (the SLURM templates set `HF_HUB_OFFLINE=1`):

```bash
python scripts/download_models.py
```

| Model | Hugging Face id |
|---|---|
| Chronos-Bolt tiny, mini, small, base | `amazon/chronos-bolt-tiny`, `amazon/chronos-bolt-mini`, `amazon/chronos-bolt-small`, `amazon/chronos-bolt-base` |
| Chronos-T5 mini, small | `amazon/chronos-t5-mini`, `amazon/chronos-t5-small` |
| Timestral-28M | `mistralai/Timestral-28M` |
| TimesFM 2.5 | `google/timesfm-2.5-200m-pytorch` |

### Data

- **Synthetic** sources (AR(1), AR(2), oscillating AR(2), AR(1) with t(3) noise, and the Markov-switching AR(1) laws) are generated by the code; every run uses the seed 20261104.
- **Real** sources are three datasets of the [TIME benchmark](https://github.com/zqiao11/TIME) (Hugging Face dataset [`Real-TSF/TIME`](https://huggingface.co/datasets/Real-TSF/TIME)): `epf_electricity_price/H` (electricity price), `ECDC_COVID/D` (COVID-19 cases) and `SG_Weather/D` (air temperature, variate 1). Download the dataset so that it sits in `data/TIME/` (or set `HSC_DATA_DIR` to the folder that contains `TIME/`):

  ```bash
  hf download Real-TSF/TIME --repo-type dataset --local-dir data/TIME
  # check: data/TIME/ECDC_COVID/D/data-00000-of-00001.arrow
  ```

### Hardware and runtimes

Every GPU job ran on a single NVIDIA A2 (16 GB) under SLURM; CPU jobs used 16 cores. `slurm/` has generic templates (`run_gpu.sbatch`, `run_cpu.sbatch`); replace the `<PARTITION>`, `<QOS>` and `<ACCOUNT>` placeholders and run `mkdir -p logs` first. Approximate wall-clock times from our job logs:

| Run | Time |
|---|---|
| Main run, one model on all seven sources (Chronos-Bolt, Timestral) | 1.5–4 min |
| TimesFM 2.5 on all seven sources | about 10 min |
| Chronos-T5 sample pipeline, one source (five models) or one Chronos-T5 variant | 1–1.5 h |
| Regime switching, mechanism and probe runs | 3–12 min each |
| Residual-noise baseline, one source (9M Monte Carlo paths, 16 CPUs) | about 9 min |
| Each report script (CPU, stored outputs only) | seconds to a few minutes |

## Reproducing the results

Each run writes `<source>/<model>.json` (summary) and `<source>/<model>.npz` (per-context arrays) under its results folder. The report scripts read the `.npz` arrays, which are not in git (they total about 1.2 GB), and write `summary.json` and `tables.md`. The small summaries that back the report are committed in `results/`. Below, `gpu` stands for `sbatch slurm/run_gpu.sbatch` and `cpu` for `sbatch slurm/run_cpu.sbatch` (or run `python -m ...` directly); `<src>` loops over the sources named.

## Running the tests

```bash
uv run pytest -q
```

The tests are exact or Monte Carlo checks of the pipeline (quantile representation, AR laws, the gap, the baselines, the sample pipeline, regime switching and the residual-noise baseline). Two tests skip by default: the TimesFM model checks (run them after `uv sync --extra timesfm`; about 6 minutes on CPU) and one accuracy-link check that needs the main run's `.npz` arrays.
